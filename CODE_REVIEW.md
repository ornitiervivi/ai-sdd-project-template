# CODE_REVIEW.md

## Checklist de revisão técnica

- A mudança atende à especificação?
- O escopo foi mantido mínimo?
- Há testes proporcionais ao risco?
- A documentação viva foi atualizada?
- A arquitetura continua coerente?
- Há regressões de segurança?
- Há impacto de compatibilidade?
- Nomes, métodos e classes são expressivos?
- Código, contratos técnicos e documentação técnica usam inglês de forma consistente?
- A mudança evita mistura de idiomas no projeto?
- Complexidade está baixa?
- Erros são tratados de forma consistente?
- Logs evitam dados sensíveis?
- Dependências novas são justificadas?
- Em Java/Spring, classes de regras de negócio têm 100% de cobertura de linhas e branches?
- Em Java/Spring, a solução aplica Clean Code, Clean Architecture, SOLID e design patterns quando fazem sentido?
- Em Java/Spring, bibliotecas para reduzir boilerplate foram consideradas quando deixam o código menor e mais limpo?
